# 项目说明文档（infinite-canvas 无限画布）

本文档基于当前仓库（版本 v0.20.0）整理，说明项目定位、功能范围，以及启动、测试、打包方式。

## 一、项目介绍

### 1. 项目是什么

「无限画布（infinite-canvas）」是一款面向图片创作的开源工作台。它把画布编排、AI 图片生成、参考图编辑、对话助手、提示词库和素材沉淀放在同一个界面里，适合用来探索视觉方案并连续迭代图片结果。

- 技术栈：Vite + React 19 + React Router 7 + TypeScript + Ant Design 6 + Tailwind CSS 4 + Zustand。
- 数据存储：纯前端方案，AI API Key、画布、素材、生成记录默认全部保存在浏览器本地（IndexedDB / localforage），无后端业务服务器；AI 请求由浏览器前台直连用户配置的 OpenAI 兼容 / Gemini 接口。
- 开源协议：MIT License。

### 2. 核心功能

| 功能模块 | 说明 |
| --- | --- |
| 无限画布 | 多画布项目、节点拖拽缩放、连线、小地图、撤销重做、导入导出 |
| AI 创作 | 浏览器前台直连 OpenAI 兼容接口，支持文生图、图生图、参考图编辑、文本问答、音频和视频生成 |
| 画布助手 | 围绕选中节点和上游节点对话、生图，并把结果插回画布 |
| 本地 Agent | 通过本机 Canvas Agent 连接 Codex / Claude Code，让 Agent 通过 MCP 操作当前画布 |
| Codex App 插件 | 安装后自动注册 MCP 并尝试拉起本地 Agent |
| 插件系统 | 通过 URL 动态安装 / 启用 / 更新 / 卸载远程节点插件，提供 TypeScript SDK 开发画布节点插件 |
| 自定义接口调用 | 可自定义生图 / 视频接口的调用脚本，适配各类中转站与自建服务 |
| 提示词库 | 内置 7 个开源提示词来源，支持自定义标准 JSON 来源，浏览器直连并缓存到 IndexedDB |

### 3. 目录结构（关键部分）

- `web/`：前端主工程（Vite + React），页面在 `web/src/pages/`，画布组件在 `web/src/components/canvas/`，画布状态在 `web/src/stores/canvas/`，画布工具函数在 `web/src/lib/canvas/`，外部服务请求在 `web/src/services/api/`。
- `canvas-agent/`：本地 Canvas Agent（供 Codex / Claude Code 通过 MCP 操作画布）。
- `canvas-proxy/`：本地转发代理（解决浏览器 CORS 问题）。
- `plugins/infinite-canvas`：Codex app 插件。
- `docs/`：文档站与项目文档内容。
- `Dockerfile` / `docker-compose.yml` / `nginx.conf`：Docker 打包与部署。
- `vercel.json` / `render.yaml`：Vercel / Render 一键部署配置。

## 二、如何启动

环境要求：Bun（推荐，Docker 构建基于 oven/bun:1.3.13）。

### 1. 本地开发启动

```bash
cd infinite-canvas
cd web
bun install
bun run dev
```

- 开发服务器监听 `0.0.0.0:3000`，浏览器访问 `http://localhost:3000`。
- 首次打开后进入右上角配置，填入自己的 OpenAI 兼容 `Base URL` 和 `API Key`（默认预置 OpenAI、Gemini 两个渠道，需填 Key 才可用）。
- 如果默认接口调用方式与你的 API 不同，可自定义生图 / 视频脚本调用。

### 2. Docker 运行

```bash
docker compose up -d
```

- 运行后默认端口 3000，访问 `http://localhost:3000`。

### 3. 其他启动方式

- `bun run start`：`vite preview` 方式预览构建产物（端口 3000）。
- Vercel：仓库根目录 `vercel.json` 直接构建 `web/`，导入仓库即可部署。
- Render：README 中的 Render Deploy 按钮 / `render.yaml`。
- 启动文档站：`docs/` 目录下另有一套文档站工程，进入后执行 `bun run dev`。

## 三、如何测试

当前项目没有专门的单元测试用例目录（`web/src/` 下无 `*.test.*` 文件），测试以「类型检查 + 格式检查 + 手动验收」为主：

```bash
cd web

# TypeScript 类型检查（最常用的回归验证手段）
bun run typecheck

# Bun 测试（脚本已配置，当前仓库内暂无用例，跑一次确认无报错即可）
bun test

# 格式检查 / 格式化
bun run format:check
bun run format
```

手动验收路径：启动开发服务器后在浏览器中验证画布操作（建节点、连线、生图、生视频、打组、导入导出等）与配置弹窗各选项。

注意：按仓库约定（AGENTS.md），AI 开发过程中不要求执行构建与测试，用户会自行验证。

## 四、如何打包

### 1. 前端产物打包

```bash
cd web
bun run build
```

- 产物输出到 `web/dist/`，为纯静态文件，任何静态托管（Nginx、Vercel、对象存储等）都能部署。

### 2. Docker 镜像打包

```bash
docker build -t infinite-canvas .
docker run --rm -p 3000:3000 infinite-canvas
```

- 多阶段构建：第一阶段基于 `oven/bun:1.3.13` 执行 `bun install` + `bun run build`；第二阶段基于 `nginx:1.27-alpine`，把 `web/dist` 作为静态资源，配 `nginx.conf` 与运行时注入脚本，暴露 3000 端口。
- 仓库内另有 `infinite-canvas.tar`（镜像归档）与 `docker-compose.local.yml`（本地 compose 变体）。

### 3. 云端部署

- Vercel：`vercel.json` 已配置构建 `web/`。
- Render：`render.yaml` 已配置，支持一键 Deploy。
