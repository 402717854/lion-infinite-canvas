# 需求 6：选择模型和分辨率后显示用了多少算力

来源：`PRD/需求文档/试用体会需求修改方案.md`（原「2026年11月1日试用体会」需求修改方案），本文档为按功能拆分后的单需求方案。

## 现状

- 项目目前**没有任何算力/积分/计费概念**（全局检索无 credit/算力相关业务代码），AI 调用是浏览器直连用户自己的 API，费用发生在渠道商侧。
- 模型与分辨率的选择位置：图片设置浮层 `canvas-image-settings-popover.tsx`（模型、size、quality、count）、文本/视频/音频各有对应 settings popover。

## 方案（两种思路，取决于数据来源，需先确认）

### 思路 A：静态估算表（不依赖接口，先做这个）

1. 在渠道模型定义上扩展一个可选的 `costHint`（如「每次 2 算力」「1K 1 算力 / 2K 3 算力」），由用户在渠道编辑里自行填写（不同中转站计费不同，无法内置统一价格）。
2. 在各设置浮层底部加一行只读文案：`预计消耗：{模型 costHint} × {count} 张`，随模型 / size / count 选择即时更新。
3. 优点：零外部依赖、贴合纯前端架构；缺点：数字靠人工维护，只是估算。

### 思路 B：实时余额查询（依赖中转站能力）

1. 多数 OpenAI 兼容中转站提供余额查询接口（如 `/v1/dashboard/billing/...` 或站点自定义接口）。在渠道配置里加「余额接口路径」可选项，前端定时/手动拉取当前余额并显示在顶栏或设置浮层。
2. 「本次将消耗多少」仍需要思路 A 的估算表配合，余额接口只能给「还剩多少」。
3. 优点：接近真实算力；缺点：各站接口不统一，逐站适配，且浏览器直连可能遇到 CORS。

## 待确认（关键）

- 试用方使用的渠道商是哪一家？其计费单位（算力/额度/美元）与是否有余额查询 API？
- 「算力」是指渠道商的积分体系还是需要项目自建一套用户额度体系？后者涉及后端/账号体系，与当前纯前端架构冲突，工作量远大于前端改造，需明确范围。
